# odoo-course
## Блок 1: налаштування середовища

Скріншоти лежать у папці `screenshots/`.

Odoo запущено з `http_interface = 127.0.0.1` в `odoo.conf`, тому в журналі `running on localhost:8069` замість `0.0.0.0:8069`. Причина: це робочий ноутбук, і Odoo не повинен бути доступний з мережі.

## Блок 2: модуль hr_hospital
Модуль лежить у підпапці `hr_hospital/`, а не в корені репозиторію.
Причина - Odoo бере технічну назву модуля з імені папки.
Крім того, так у репозиторії можна тримати кілька модулів.
Альтернатива була - покласти `__manifest__.py` у корінь репозиторію.
Я від неї відмовився: після `git clone` папка називалася б `odoo-course`, і посилання `hr_hospital.xxx` не працювали б.

## Блок 3: розширення hr_hospital
Ознаку «Лікар є інтерном» беру з галочки `is_internship` на кваліфікації, а не з порівняння через `env.ref('hr_hospital.doctor_category_intern')`.
Причина - `env.ref` впаде, якщо цей запис видалять, і не врахує нову інтернську кваліфікацію (напр. «Інтерн-хірург»).
У візиті наявне поле `visit_date` стало фактичною датою, а для запланованої додано `planned_date`, щоб не ламати блок 2; звіт по візитах фільтрує за `planned_date`.
Заборона видаляти завершені візити пропускає контекст `_force_unlink`, інакше видалення модуля писало б у лог `ERROR`.
Повний шлях хвороби зберігається в полі `complete_name` (`recursive=True`), бо `display_name` не зберігається в базі й батько не встигав порахуватися.
